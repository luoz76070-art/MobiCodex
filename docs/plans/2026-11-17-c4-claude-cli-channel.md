# C4 Claude CLI 控制通道（设计稿）

2026-11-17。用户决定保留现有的 Claude Code 插件通道（C3 取消），另加一条由网关自己运行 Claude Code 的控制通道。

## 现状和缺口

现有通道是装在 Claude Code 里的插件（`plugins/mobile-claude`），它只能跟随**电脑上正开着**的会话：

- 不能从手机新建会话，也不能继续已经关掉的历史会话；
- 历史不能向前翻页；
- 审批只有“允许一次 / 拒绝”，没有“总是允许”；
- 电脑上的会话一关，手机就什么都做不了。

## 新通道能做什么

1. 列出电脑上所有 Claude Code 会话（按项目分组，按最近修改排序），读历史并可向前翻页。
2. 从手机继续任一历史会话，或在选定的项目里新建会话。
3. 实时显示输出；发消息时可排队（等这一轮结束）或即时追加。
4. 中断正在跑的一轮。
5. 工具审批：允许一次 / 总是允许（写入该项目的本地权限规则）/ 拒绝（可附一句理由给 Claude）。
6. 回答 Claude 的提问（单选、多选、自由回答）。
7. 切换权限模式（default / plan / acceptEdits）和模型。**不提供** bypassPermissions。

## 实现方式

网关（`apps/relay`，Node/TypeScript）引入官方 Claude Agent SDK（`@anthropic-ai/claude-agent-sdk`，锁定版本），新增 `claudeCliAdapter`，实现现有的 `SessionAdapter` 接口，所以手机端沿用同一套会话界面。

| 能力 | SDK 接口 |
|---|---|
| 会话列表、历史翻页 | `listSessions({ dir, limit })`、`getSessionMessages(id, { dir, limit, offset })`、`getSessionInfo` |
| 继续 / 新建 | `query({ prompt: 输入队列, options: { cwd, resume, includePartialMessages: true, canUseTool, permissionMode: "default", settingSources: ["user", "project", "local"] } })`（流式输入模式） |
| 发消息 | 往输入队列里放一条用户消息 |
| 中断 / 关闭 | `Query.interrupt()` / `Query.close()` |
| 审批、提问 | `canUseTool` 回调挂起，等手机答复；回调的 `signal` 取消时撤回手机上的卡片。“总是允许”回传回调给出的 `suggestions` 里目标为本地设置的那条 |
| 切模式、切模型 | `Query.setPermissionMode()`、`Query.setModel()` |

- 运行的是电脑上已安装的 `claude`（`pathToClaudeCodeExecutable`），登录和配置都与用户平时一致。网关启动时检查版本，太旧就在手机上提示升级。网关不读取、不转存任何登录凭据。
- 用量计入电脑上 Claude Code 当前登录的账户或渠道。

## 和现有插件通道的关系

- 手机上另开一个 Agent，名为“Claude CLI”（用户 11-17 定），和插件通道的“Claude Code”并列，界面沿用统一布局。插件已登记的会话在“Claude CLI”列表里标“电脑上开着”，点进去提示到“Claude Code”里操作。
- **同一会话只允许一个写入方。**
  - 插件已登记该会话：走插件通道，新通道不碰它。
  - 会话记录最近 2 分钟内有写入、但插件没登记（可能开在终端里）：默认不让“继续”，改为提供“分叉继续”（`forkSession`，生成新会话，原会话不动）。
- 插件通道的代码不改。W3b（交接时新建 Claude 会话）改用本通道新建，不再走定时任务文件。

## 安全和资源上限

- 只能在网关配置里列出的目录新建会话（用户 11-17 定）；手机上不能输入任意路径。继续历史会话也只限这些目录下的会话。
- 权限模式默认 `default`：所有需要确认的操作都到手机上审批。
- 最多同时运行 3 个会话进程。一轮结束、且 15 分钟没有手机在看，就关闭进程；会话记录还在，随时可以再继续。
- 审批或提问最长等 30 分钟，超时按拒绝处理并中断这一轮。
- 网关重启时，它启动的进程随之结束，待答的审批作废；手机显示“已断开，可继续”。
- 手机端的输入、审批都要经过现有的配对令牌校验，和其他 Agent 一致。

## 用户决定（11-17）

1. 另开“Claude CLI” Agent，不和“Claude Code”合并。
2. 会话正开在终端里时怎么处理：待定（分叉继续，或拒绝）。
3. 只允许网关配置里列出的目录。

### C4b 实施决定（覆盖上面的暂定分叉方案）

插件已登记，或最近两分钟有非本网关写入，均拒绝继续并返回 CLAUDE_CLI_SESSION_BUSY；本期不提供分叉。审批和 AskUserQuestion 自动拒绝并显示系统提示，手机交互留待 C4c。执行文件、兼容版本依据、接口、进程回收与验收边界见 [C4b 实施记录](2026-11-17-c4b-claude-cli-run.md)。
